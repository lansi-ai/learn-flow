# 看板指南（board-guide.md）

## 01. 设计原则：一处维护，一处派生

学习的最大管理成本不是「学」，是**台账对不上**：笔记本一套、表格一套、脑子一套，三套互相矛盾，最后谁也不信，于是都不看了。

所以本体系只允许一个源：

```
docs/board.yaml          ← 唯一事实源（人写）
      │  python scripts/build-board.py
      ▼
docs/board-html/index.html   ← 派生物（机器写，禁止手改）
```

铁律：

- **状态只改 YAML**，改完重跑脚本。
- **HTML 一旦手改，下次生成就被覆盖**，所以干脆别改。
- 汇报进度时引用 YAML 的行，不要引用「我记得」。

---

## 02. 为什么学习看板必须是双轴

普通任务看板只有 `status`（待办/进行中/完成）。学习场景不够，会直接导致看板说谎：

- 一本书「读完」了 = `done`，但一个字复述不出来 → 看板显示 100% 完成，人却什么都不会。
- 一个练习「做过」了 = `done`，但是照着模板抄的 → 同上。

所以本体系用**双轴**：

| 轴 | 字段 | 取值 | 回答的问题 |
|---|---|---|---|
| 生命周期 | `status` | `todo` / `doing` / `blocked` / `done` | 这件事推进到哪了 |
| 能力水平 | `mastery` | `0`–`4` | 我到底会不会 |

**关键设计：允许 `status=done` 且 `mastery=1`。** 这不是 bug，这是这个看板存在的理由——它逼你看见「我做完了但没学会」这件事。看板上会显示为**空心完成的橙色标记**，一眼扎眼。

如果哪天你发现所有 `done` 的 `mastery` 都是 3–4，两种可能：要么你真的学得好，要么你在给自己放水。后者更常见。

## 03. `board.yaml` 结构

```yaml
project: 自媒体运营学习
goal: 6 个月内能稳定做出单条 5 万播放的科普视频
updated: 2026-10-26

metrics:
  - name: 完播率
    def: 完整播放次数 / 播放次数
  - name: 3 秒留存
    def: 播放超过 3 秒的人数 / 曝光人数

domains:
  - id: topic
    name: 选题力
    priority: P0
    units:
      - id: TP-01
        name: 爆款选题拆解
        mastery: 2
        target: 3
        tasks:
          - id: TP-01a
            title: 拆解 10 条同垂类爆款并归纳钩子模板
            status: doing
            type: 练
            mastery: 1
            created: 2026-10-26
            date:
            dep: []
            goal: 能写出 3 个可复用钩子模板并被同事认可
            evidence: docs/practice/topic/TP-01a.md
            data:
            review_due:
            note:
```

### 字段说明

| 字段 | 层 | 必填 | 说明 |
|---|---|---|---|
| `project` / `goal` / `updated` | 顶层 | ✅ | 项目名、能力终点、最后更新日 |
| `metrics` | 顶层 | | 指标口径说明（改口径必须同步改 `LEARN-RULES.md`） |
| `domains[].id/name` | 域 | ✅ | 域编号与名称；`id` 只增不改 |
| `domains[].priority` | 域 | | `P0/P1/P2` |
| `domains[].units[].id/name` | 单元 | ✅ | 单元编号 |
| `units[].mastery` | 单元 | ✅ | 0–4，当前掌握度 |
| `units[].target` | 单元 | | 目标掌握度，默认 3 |
| `tasks[].id` | 任务 | ✅ | **稳定编号，只增不改**（改了历史引用全断） |
| `tasks[].title` | 任务 | ✅ | 标题 |
| `tasks[].status` | 任务 | ✅ | `todo/doing/blocked/done` |
| `tasks[].type` | 任务 | ✅ | `学/练/产/复` 四类之一 |
| `tasks[].mastery` | 任务 | | 该任务达成后的掌握度 |
| `tasks[].created` | 任务 | ✅ | 创建日期，燃尽/趋势依赖 |
| `tasks[].date` | 任务 | | 完成日期，仅 `done` 填 |
| `tasks[].dep` | 任务 | | 依赖的任务 id 列表 |
| `tasks[].goal` | 任务 | | 目标行为（门禁 1 的落点） |
| `tasks[].evidence` | 任务 | | 产出物路径或链接（门禁 2 的落点） |
| `tasks[].data` | 任务 | | 外部反馈数据，键值对或文本 |
| `tasks[].review_due` | 任务/单元 | | 复习到期日 |
| `tasks[].note` | 任务 | | 备注 / 卡点 |

### `type` 四类的意义

| type | 含义 | 典型时长 | 占比参考 |
|---|---|---|---|
| `学` | 输入：看、读、听 | 30–90 min | ≤ 30% |
| `练` | 动手复现，允许看材料 | 45–120 min | ≥ 40% |
| `产` | 独立产出，不许看模板 | 2–6 h | ≥ 20% |
| `复` | 回看、闭卷检验 | 10–20 min | 按复习曲线 |

**如果 `学` 类任务占比超过 50%，看板顶部会显示警告**——这是输入囤积症的典型体征。这个警告是本体系最重要的一条自动诊断。

## 04. 生成器契约

脚本：`scripts/build-board.py`（从技能 `assets/build-board.py` 复制，不要重写）

```bash
python scripts/build-board.py                # 读 docs/board.yaml，写 docs/board-html/index.html
python scripts/build-board.py --check        # 只校验，不出 HTML
```

要求：

- 依赖：仅 PyYAML
- 输出：**单文件离线 HTML**，内联全部 CSS/JS，无任何外链，双击即开、可截图、可直接发人
- **内容由脚本生成，JS 只负责视图切换与筛选**（JS 挂了也不能白屏）
- 自动校验：必填字段缺失、`id` 重复、`done` 无 `evidence`、`status` 非法 → 以 `⚠` 列出，不阻断生成

### 四个视图

| 视图 | 内容 | 用途 |
|---|---|---|
| **概览**（默认） | 统计卡 + 各域掌握度条 + 状态分布 + 复习到期 + 类型占比 + 内容数据 | 一眼看全局，30 秒判断「我在真学还是假学」 |
| **看板** | todo / doing / blocked / done 四列 | 决定今天做什么 |
| **能力树** | 域 → 单元 → 任务 三级展开 | 看结构缺口，哪块是空的 |
| **矩阵** | 域 × 掌握度分布 | 发现偏科 |

### 概览页必须回答的四个问题

1. **我在真学吗？** → `学/练/产` 类型占比（`学` > 50% 报警）
2. **我做完了但没学会吗？** → `done` 但 `mastery ≤ 1` 的数量
3. **我该复习什么？** → `review_due ≤ 今天` 的列表
4. **我的产出有效吗？** → 有 `data` 的任务的外部指标趋势

看板如果回答不了这四个问题，就是装饰品。

## 05. 更新节奏

| 时机 | 动作 |
|---|---|
| 开工 | 状态置 `doing` → 重跑脚本 |
| 收口 | 置 `done` + 补 `evidence` + 更新 `mastery` + 排 `review_due` → 重跑脚本 |
| 每天 | 只看概览的「复习到期」，先复习再学新 |
| 每周 | 看类型占比与掌握度分布，调下周一件事 |
| 每月 | 归档完成史到 `docs/archive/`，看板只留当前窗口 |

**行数预算**：`board.yaml` ≤ 500 行。超了先归档已完成任务，不要靠删信息瘦身。

## 06. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 看板 HTML 没变 | 改了 YAML 没重跑脚本 | `python scripts/build-board.py` |
| 任务显示进行中但早做完了 | 状态没改 / 没补 `date` | 改 YAML 后重跑 |
| 概览报「done 缺证据」 | 完成时没填 `evidence` | 补证据，补不出就把状态改回 `doing` |
| 掌握度看着漂亮但不踏实 | 自评放水 | 逐个单元问「能不看材料做一遍吗」，答不出降级 |
| 想直接改 HTML 调样式 | — | 改脚本里的模板，不要改产物 |
