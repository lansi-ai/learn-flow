# 目标澄清指南（goal-breakdown-guide.md）

## 01. 本指南要解决什么

大多数学习计划死在第 3 天，原因几乎都不是「不够努力」，而是**第一天就没想清楚「学会」长什么样**。

典型死法：

- 「我要学短视频运营」→ 学什么？看什么？学到哪算完？全无定义 → 刷了 200 条干货，一条视频没发。
- 「我要学英语」→ 目标无限大 → 每天都学，每天都感觉没进步 → 三个月放弃。
- 「我要考过 XX 证」→ 这个还行，因为有客观终点 → 所以**凡是能绑定客观终点的，先绑**。

本指南的作用：用 5 个维度把模糊愿望压成一个**可验证的能力终点 + 可达成的首月范围**。

---

## 02. 五维追问框架

从中**精选 3–5 个**，不要全问。必含第 1、2、3 维。

### 维度 1：终点行为（必问）

不要问「你想学到什么程度」，要问：

> **3–6 个月后，你能独立做到什么，是别人能看见、能验证的？**

追问技巧——把答案往「行为 + 标准」上逼：

| 用户说 | 继续问 |
|---|---|
| 「能熟练做短视频」 | 熟练到什么程度？播放量、完播率、还是能稳定日更一个月？ |
| 「能看懂财报」 | 给你一份没看过的财报，你能在多长时间内说出它的三个风险点？ |
| 「英语能交流」 | 跟谁、聊什么话题、聊多久不卡壳？ |
| 「会写代码」 | 能独立从零写一个什么？不看教程的那种 |

**合格的终点行为**，三个条件同时满足：

1. **可观察**：有产物或行为，不是心理状态（「有感觉」「有思路」不合格）
2. **有标准**：有阈值、有时限、或可对照清单判定
3. **可复现**：不是「那次运气好」，是稳定能做到

范例对照：

- ❌ 学会短视频运营
- ✅ 能不看模板独立写出 3 个不同钩子的开头，且发布后完播率 ≥ 40%
- ❌ 掌握 Python
- ✅ 能独立写一个抓取网页数据并导出 Excel 的脚本，含异常处理，别人能跑通
- ❌ 提升表达能力
- ✅ 能在 3 分钟内向没背景知识的人讲清一个专业概念，对方能复述出要点

### 维度 2：起点诊断（必问）

> **现在这条路上，你已经能独立完成到哪一步？逐环节说，别给理想值。**

关键在「**独立**」和「**逐环节**」。绝大多数人会高估起点，方式有两种：

- **把「看得懂」当「做得出」**：看得懂别人的脚本 ≠ 自己能写
- **把「做过一次」当「会做」**：跟着教程成功过一次 ≠ 能独立复现

追问技巧：

- 「这一步你现在不看教程能做出来吗？上次独立做是什么时候？」
- 「如果现在让你现场做一次，你估几分把握？低于 7 分就按不会算。」

**处理虚高自评**：如果用户自评「能独立做」，但拿不出任何作品，必须直接说：

> 这一步我按「能认」记（掌握度 1），因为暂时没有作品能证明到「独立做」。等你交一个出来我立刻调上去——不是不信你，是不想让计划建在虚高的地基上。

### 维度 3：时间预算（必问）

> **每周真实能投入几小时？按过去三个月的实际情况估，不按你希望的。**

追问：

- 「工作日晚上一般几点能空出来？能连续 1 小时不被打断吗？」
- 「周末有多少是真正自由的？」

**换算规则**（写进计划时用）：

- 用户报 10 小时 → 按 **7 小时**排（打七折，这是历史规律）
- 碎片时间（通勤、排队）单独算，只安排「输入类」任务，不安排「产出类」
- **产出类任务需要连续时间块**，低于 45 分钟的整块排不进去

### 维度 4：失败模式（选配，但强烈建议问）

> **你以前学过类似的东西吗？上次是怎么断的？**

以及本技能阶段 1 的**第 0 问**：

> **做这件事的时候，最容易骗自己的方式是什么？**

这个问题决定了门禁怎么设计。常见答案与对应门禁：

| 用户的失败模式 | 该强化哪条门禁 |
|---|---|
| 「看了很多，但从不做」 | 强制 `练 / 产` 类任务占比，`学` 类任务设上限 |
| 「一直在准备，不敢发」 | 设发布截止日；允许「60 分就发」 |
| 「做一半就换方向」 | 锁定首月 MVP，新增方向一律进「不做清单」 |
| 「只看数据不好就放弃」 | 设最低样本量（发满 10 条再评估），前期不看涨粉 |
| 「报了课就当学了」 | 报课不算进度；只认产出物 |

### 维度 5：MVP 划界（必问）

> **这个月如果只能交付一件事，你要哪件？另外三件明确先不做。**

两问合一：既问「要什么」，也逼「不要什么」。**没有不做清单的计划一定会膨胀**。

判断标准：

- 首月 MVP 必须能在**用户时间预算的 60% 内**完成（留 40% 缓冲给意外）
- 必须能产出**一个可展示的东西**（一条视频、一个脚本、一份报告）
- 必须覆盖**最关键的短板**，而不是最容易的那块

## 03. 收敛判定

四项都清晰即可收敛，不必问到完美：

1. 能力终点（可验证行为）
2. 当前差距（逐环节自评）
3. 核心路径（先补哪块、为什么）
4. 首月 MVP（要什么 + 明确不做什么）

若用户对第 1 或第 5 项答不上来，**不要替他编**。换个问法再试一次；仍答不上就建议：

> 终点定不下来，通常是因为还没见过「做得好」长什么样。建议先花 3 天做一次**对标拆解**（找 10 个同方向的成果，逐个拆它凭什么成立），拆完再回来定终点——这 3 天本身就是一个 C 级任务。

## 04. 共识小结模板

```text
📋 【学习体系共识】

🎯 能力终点：<可验证行为，含标准>
📉 当前差距：
   - <环节 1>：自评 X 分（证据：<有/无>）
   - <环节 2>：……
🛤 核心路径：先补 <X>，因为 <理由>；暂不动 <Y>，因为 <理由>
📦 首月 MVP：交付 <一个具体产物>；明确不做 <1–3 项>

⚠️ 需要你知道的假设：<如：按每周 7 小时排期>

❓ 以上是否完善？有补充请说；回复「确认」我才落盘。
```
