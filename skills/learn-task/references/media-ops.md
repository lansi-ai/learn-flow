# 自媒体运营领域包（media-ops.md）

> 本文件是 `learn-flow` 的领域增量，不重复通用纪律。通用门禁、掌握度、看板规则见 `learn-task/SKILL.md` 与项目 `docs/LEARN-RULES.md`。
> 用法：目标为「做自媒体 / 做内容账号 / 短视频运营」时加载本文件，把这里的口径与流水线填进能力地图。

---

## 01. 这个领域为什么特别适合本体系

自媒体运营有一个别的学习方向没有的优势：**它有客观、快速、免费的外部反馈**。

- 学英语：要考一次试才知道水平，周期数月
- 学编程：要等项目上线才知道行不行
- 做内容：**发出去 24 小时就有数据**，几十到几十万人的真实行为

这相当于开发里的「测试套件现成可用」。所以本体系在自媒体场景下的门禁可以更硬——**不用靠自评，靠数据说话**。

前提是：你得真的把数据回填进看板。不回填，这个优势就没了。

## 02. 分阶段北极星指标（新手最容易错的地方）

**不同阶段盯不同指标。盯错了会直接放弃。**

| 阶段 | 粉丝量 | 北极星指标 | 暂时别看 | 为什么 |
|---|---|---|---|---|
| 起号期 | 0–1000 | **发布率**（本周计划发 N 条，实际发了几条）+ 完播率 | 涨粉、播放量 | 起号期没有流量池，播放低是正常的；此时唯一该练的是「稳定产出 + 内容完整」 |
| 成长期 | 1000–1 万 | **完播率 + 收藏率** | 总播放 | 算法开始给你推流，能不能留住人决定能不能破圈 |
| 破圈期 | 1 万–10 万 | **涨粉率 + 爆款率** | 单条播放 | 泛流量会骗人：100 万播放不涨粉，账号等于没长 |
| 变现期 | 10 万+ | **转化率 / 商业询单** | 涨粉 | 粉丝不再等于收入 |

**起号期只看涨粉 = 自杀。** 这是新手放弃的第一大原因，必须在计划里写死。

指标定义（写进 `board.yaml` 的 `metrics`，改口径必须双写）：

| 指标 | 定义 | 备注 |
|---|---|---|
| 完播率 | 完整播放次数 / 播放次数 | 长视频看「平均播放时长 / 总时长」更准 |
| 3 秒留存 | 播放超 3 秒人数 / 曝光人数 | 检验钩子的唯一指标 |
| 收藏率 | 收藏数 / 播放数 | 知识类、工具类的核心指标，比点赞更能反映价值 |
| 互动率 | (赞+评+藏+转) / 播放 | 破圈信号 |
| 涨粉率 | 新增粉丝 / 播放 | 判断流量是否「对口」 |
| 主页点击率 | 主页访问 / 播放 | 判断内容是否引发「想了解更多」 |

## 03. 内容流水线（六段，对应六个能力域）

```
选题 → 对标拆解 → 脚本 → 制作 → 发布 → 数据复盘
  ↑                                          │
  └──────────── 沉淀回选题库 ←────────────────┘
```

| 段 | 真实难点 | 对应能力域 | 达标信号 |
|---|---|---|---|
| 选题 | 不是「想讲什么」，是「谁在什么处境下需要这个」 | 选题力 | 能用一句话说出「这条替谁解决了什么」 |
| 对标拆解 | 不是「看别人怎么拍」，是「拆它凭什么成立」 | 选题力 / 结构力 | 能拆出可复用的结构模板，而不是感叹「拍得真好」 |
| 脚本 | 前 3 秒决定 80% 的结果 | 脚本力 | 开头 3 秒能被陌生人看懂且想继续 |
| 制作 | 完备性陷阱：永远觉得还能再改 | 制作力 | 能在自定截止时间内交出一个「60 分可用」的版本 |
| 发布 | 发布是决策，不是动作 | 账号力 | 固定时间、固定栏目、可预期 |
| 复盘 | 90% 的人只看数字，不归因 | 数据力 | 能说出「这条为什么好/差」且下次能复用 |

**每段都可独立练。** 不要一上手就练「做一条完整视频」——那是综合考试，不是练习。先单练选题（不拍），再单练开头（不剪全片）。

## 04. 对标拆解四问（最值得先练的单项）

找 10 条同垂类、数据明显好的内容，每条回答四问：

1. **它替谁解决了什么？**
   不是「讲 AI」，是「让不懂技术的老板能在会上说清 AI 能干什么」。写到这个粒度才算答对。

2. **前 3 秒用了什么钩子？**
   归类到五种：`问题`（你还在…吗）/ `冲突`（所有人都说 A，其实错）/ `反常识`（越努力越穷）/ `结果前置`（我用这招涨了 3 万粉）/ `身份认同`（做运营的都懂）。

3. **结构是什么？**
   常见四种：`总分总`（观点→三点→回收）/ `悬念递进`（每段留钩子）/ `清单`（N 个方法）/ `故事`（人物+转折+结论）。

4. **它省略了什么？**
   这条最容易被跳过，也最有价值。好内容的核心能力是**敢删**。列出它没讲的、跳过的、一笔带过的——那些正是它节奏好的原因。

**产出物**：一份 `docs/practice/topic/对标拆解.md`，10 条 × 4 问 + 一页「可复用模板归纳」。
**验收**：归纳出的模板能直接套用到自己的选题上，且不显得生硬。

## 05. 单变量实验法（把「碰运气」变成「积累认知」）

一条内容 = 一次实验。**一次只改一个变量，否则数据什么都说明不了。**

动手前必须写清三行：

```yaml
假设: 把开头从「背景介绍」改成「结果前置」，3 秒留存会提升
变量: 开头类型（其他全部保持不变）
预期: 3 秒留存 ≥ 45%，完播率提升 ≥ 5 个点
```

可实验的变量（按性价比排序）：

1. **开头 3 秒**（影响最大，改动成本最低）
2. **标题 / 封面**（决定点击，不影响完播）
3. **时长**（60 秒 vs 3 分钟，测信息密度容忍度）
4. **结构**（清单 vs 故事）
5. **表达方式**（口播 vs 图文 vs 实拍）

**样本量纪律**：同一定位连发 **5–10 条**再判断趋势。单条数据差可能是选题、时间、运气，一律不作为结论。

**归因要求**：复盘必须回答「这个变量是不是真的起作用」——如果同一变量三次实验都没效果，就放弃这个假设，别硬扛。

## 06. 复盘模板

```markdown
# 复盘 · <内容标题> · <日期>

## 实验设定
- 假设：
- 本轮变量：
- 预期：

## 结果
- 播放：      完播率：      3 秒留存：
- 收藏率：    涨粉：       互动率：
- 对比基准（近 5 条均值）：

## 归因（必须答，不许只抄数字）
- 数据符合预期吗？
- 如果符合：变量起作用了，下次保留什么？
- 如果不符合：是变量没效果，还是执行没到位？（这两者要分清）
- 我这条最该删的是哪一段？

## 沉淀
- 进选题库的结论：
- 进坑档的教训：
- 下一条唯一要改的地方：
```

**「执行没到位」和「假设错误」必须分清。** 前者要练手艺，后者要换方向。混在一起就会得出「这个方法没用」的错误结论。

## 07. 七种自嗨（每一条都对应一个可检验的问句）

| 自嗨 | 表现 | 检验问句 |
|---|---|---|
| **我想讲的 = 用户想看的** | 讲得很爽，数据很惨 | 这条替谁、在什么处境下、解决了什么？说不出来就是自嗨 |
| **信息量 = 价值** | 30 秒塞 20 个点 | 陌生人看得完吗？记住几个？ |
| **专业 = 权威** | 满口中英夹杂术语 | 把术语换成大白话，还成立吗？ |
| **播放高 = 账号健康** | 一条 10 万播放涨 20 粉 | 涨粉率多少？来的流量对口吗？ |
| **没数据 = 平台限流** | 一低就说被限流 | 前 3 秒留存多少？多数问题出在这 |
| **改五个地方 = 优化** | 这改点那改点，下次不知哪起作用 | 这轮只改了什么？ |
| **日更 = 努力** | 每天发，条条凑数 | 这条我自己愿意看完吗？ |

**用法**：复盘时逐条过一遍，命中就记进坑档。这七条是自媒体领域最高频的死因。

## 08. 起号期的现实预期（写进计划，防放弃）

- 前 10 条内容通常没有流量，**这是常态，不是失败**。
- 第一条爆款往往出现在第 20–50 条之间，且常常是自己最不看好的那条。
- 起号期唯一可控的是**发布率**和**每条的改进幅度**，不是播放量。
- **不要在起号期做「账号定位」的大决策**——定位是在发了 20 条之后，从数据里长出来的，不是想出来的。

对应到能力地图：起号期把「发布率」设为首月 MVP 的验收指标，而不是「涨粉 1000」。这个选择直接决定能不能撑过第一个月。

## 09. 小样本快速通道

如果用户还没开始做、也没有账号，不要让他先学三个月再发。改成：

1. **第 1 周**：拆 10 条对标（纯输入，C 级任务）→ 产出结构模板
2. **第 2 周**：只写 5 个开头，不拍（B 级，练单项）→ 找 3 个人看，问「想不想看下去」
3. **第 3 周**：做 2 条完整内容，**允许 60 分就发**（A 级，走全流程 + 复盘）
4. **第 4 周**：看数据，归因，定下一轮唯一变量

四周就能完成一次完整闭环，比「准备三个月再发第一条」有效得多。**准备期越长，越不敢发。**
